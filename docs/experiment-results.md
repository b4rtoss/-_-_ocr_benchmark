# Результаты экспериментов с OCR манги

Исследование разделяет две задачи: распознавание уже выделенного текста (recognition-only) и OCR полной страницы, где нужно найти текстовые области и прочитать их. Их метрики и выборки оцениваются отдельно.

## Источники и статус результатов

Основной источник — презентация автора проекта, слайды 2–24. Дополнительный источник — авторский документ «MangaLMM» с качественным сравнением пяти систем на одном изображении. Для базового эксперимента на 3116 кропах метрики дополнительно пересчитаны из сохранившихся CSV Tesseract, PaddleOCR и Manga OCR: значения совпали с презентацией после округления. Числа MangaLMM совпали с сохранившимся отчётом `scaled_eval_50.txt`.

Результаты сравнения с ChatGPT перенесены из презентации, слайды 9–12. Доступная локальная копия `ocr_comparison_test50.csv` содержит пропуски результатов OCR и пустые ответы ChatGPT, поэтому она не подтверждает эту таблицу и не использована для её пересчёта. Для полного воспроизведения нужно восстановить исходные ответы и соответствующий CSV конкретного запуска.

Эти результаты относятся к исходным исследовательским запускам. Отдельный [отчёт проверки работоспособности](verification.md) описывает последующий аудит кода и пробные запуски на трёх кропах. Их время и качество нельзя смешивать с экспериментами ниже.

## Данные и подготовка

Для recognition-only использована манга Hamlet из Manga109. XML-аннотации содержат координаты `xmin, ymin, xmax, ymax` и эталонный японский текст. Скрипт автоматически вырезает области и формирует CSV с именем изображения и транскрипцией. В исследовательском наборе — 3116 текстовых кропов.

Это сравнение готовых OCR-систем и мультимодальных моделей. Обучение собственной модели в материалах не описано.

## 1. Три OCR-системы на 3116 кропах

Источник: слайд 8 и пересчёт сохранившихся CSV. CER нормализуется по числу символов эталона, Exact Match измеряет долю полностью совпавших транскрипций.

| Система | Примеры | CER ↓ | Exact Match ↑ | Среднее записанное время |
| --- | ---: | ---: | ---: | ---: |
| Tesseract | 3116 | 97,74% | 2,54% | 0,552 с |
| PaddleOCR | 3116 | 81,45% | 4,91% | 0,055 с |
| Manga OCR | 3116 | 9,13% | 70,64% | 0,241 с |

При пересчёте: пустых предсказаний 19 у Tesseract, 49 у PaddleOCR, 0 у Manga OCR. Ошибок по столбцу `status` не обнаружено; при отсутствии такого столбца оценщик считает строку успешной. Это не исключает ошибок самого распознавания.

Manga OCR показал наименьший CER и наибольшую долю точных совпадений среди трёх использованных конфигураций на этом наборе. Вывод не распространяется автоматически на другие языки, документы и настройки OCR. Скорость характеризует исходные запуски; точные версии всех компонентов и режим выполнения каждой системы в презентации не зафиксированы. Это не замер нынешней CPU-конфигурации приложения.

## 2. Четыре системы на одинаковых 50 кропах

Для сравнения с ChatGPT использована фиксированная случайная выборка: `random.seed(42)`, затем `random.sample(rows, 50)`. Все четыре системы сравниваются на одних изображениях, а не на разных наборах.

Промпт из презентации:

> Perform OCR on this cropped Japanese manga text image. Return only the recognized Japanese text. Do not translate, explain, correct, or add anything.

| Система | Примеры | CER ↓ | Exact Match ↑ |
| --- | ---: | ---: | ---: |
| Tesseract | 50 | 97,92% | 4% |
| PaddleOCR | 50 | 80,76% | 12% |
| Manga OCR | 50 | 7,45% | 76% |
| ChatGPT | 50 | 6,24% | 80% |

Источник: слайд 10, без повторного пересчёта исходных ответов ChatGPT. ChatGPT превосходит Manga OCR на 1,21 процентного пункта по CER и на 4 процентных пункта по Exact Match. Для 50 примеров это 40 точных совпадений против 38. Такая разница сама по себе не устанавливает статистически значимое превосходство. Версия ChatGPT и дата исходного запуска в презентации не указаны.

### Анализ ошибок

На слайдах 11–12 показана разница между буквальным распознаванием и восстановлением вероятной фразы по языковому контексту. Например, эталон `はいっ` распознан как `ほいっ`. В другом примере модель меняет фрагмент исходной реплики. Для OCR это ошибки, даже если ответ выглядит языково правдоподобным. Поэтому качество оценивается по эталону, а не только по беглости текста.

## 3. MangaLMM на полных страницах

Использована модель `hal-utokyo/MangaLMM` на основе Qwen2.5-VL-7B. В отличие от распознавания готового кропа, она должна выдать и координаты областей, и текст.

### Ограничения оборудования и подходы

- GPU: RTX 4050 с 6 ГБ VRAM.
- 4-битная квантизация для размещения модели в доступной памяти.
- Бюджет изображения: `MAX_PIXELS = 256 * 28 * 28`, то есть 200704 пикселя.
- В презентации для исходной работы указан максимум 2116800 пикселей, примерно в 10,5 раза больше локального лимита. Это сравнение по материалам автора проекта, без независимой проверки параметров публикации.
- Пример размера после обработки Qwen: 504 × 364. Реальный размер зависит от изображения и обработки процессором.
- На целых страницах наблюдались пропуски текста, неверные рамки и повторения.
- Исследован запуск по сетке 2 × 2: локальные координаты фрагментов переводятся в координаты страницы, затем результаты объединяются и очищаются от дубликатов.

Для приближения к методике работы использована выборка из официального MangaOCR test split: 50 изображений. Это отдельная выборка, её нельзя приравнивать к 50 кропам Hamlet. Презентация не устанавливает, что итоговые числа ниже получены именно tiled-вариантом, поэтому эффект tiled inference отдельно численно не заявляется.

### Диагностика ошибки координат

Первичная оценка дала ноль пространственных совпадений. В презентации это связано с технической ошибкой сопоставления координат. Для исправления получен фактический размер изображения после обработки Qwen через `image_grid_thw` и рассчитаны коэффициенты:

```python
scale_x = original_width / resized_width
scale_y = original_height / resized_height
```

Предсказанные координаты приведены к исходному размеру страницы. После этого пространственные совпадения появились. Это значимый инженерный результат: ошибка оценки была отделена от ошибки модели.

### Результаты после масштабирования координат

50 вызовов завершились без зарегистрированных ошибок. На 6 страницах не получилось распарсить ни одной детекции. Успешное завершение вызова не означает правильный или непустой OCR.

| Показатель | Значение |
| --- | ---: |
| Изображения | 50 |
| Эталонные области | 828 |
| Предсказанные области | 1084 |
| Пространственные совпадения | 37 |
| Detection Precision | 3,41% |
| Detection Recall | 4,47% |
| Detection Hmean | 3,87% |
| End-to-end Precision с учётом NED | 0,76% |
| End-to-end Recall с учётом NED | 1,00% |
| End-to-end Hmean с учётом NED | 0,86% |

Источники: слайды 18–23 и сохранившийся `scaled_eval_50.txt`. Схема на слайде 24 указывает порог IoU > 0,5, а scaled evaluator в коде использует IoU ≥ 0,5. Для точного воспроизведения нужно сохранять версию оценщика и правило сравнения порога. End-to-end показатели учитывают сходство распознанного текста через NED и не равны CER или Exact Match.

В локальной конфигурации качество полной обработки страницы оказалось низким. Ограничения разрешения и памяти важны для интерпретации, но их причинный вклад отдельно не измерен. Эти числа не следует представлять как воспроизведение качества авторской работы MangaLMM.

## 4. Предварительное качественное сравнение на одном изображении

Источник — отдельный авторский документ «MangaLMM». Он содержит изображение фрагмента манги с несколькими панелями, примеры ответов пяти систем и приблизительную длительность обработки. Это иллюстрация поведения моделей на одном примере. Она не заменяет оценку на размеченной выборке.

| Система | Примерное время по документу | Результат и задача |
| --- | ---: | --- |
| MangaLMM | 5–6 с | Шесть записей с координатами и японским текстом, включая два почти совпадающих бокса с одинаковым текстом |
| Manga OCR | 0,05 с | Одна транскрипция; модель предназначена для чтения выделенного текста, а не поиска областей на изображении |
| PaddleOCR | 0,63 с | Шесть фрагментов ответа; автор отмечает многочисленные ошибки |
| Tesseract | 0,75 с | Большой объём вывода с ошибочными и искажёнными символами |
| ChatGPT | 2 мин 13 с | Несколько распознанных строк; версия модели и условия запроса не зафиксированы |

В документе не указаны точные версии моделей, параметры, число повторов, включение загрузки модели в замер и способ измерения времени ChatGPT. Более того, Manga OCR выполняет иную задачу, чем системы с детекцией. Поэтому из этой таблицы нельзя выводить общий рейтинг скорости или подменять ею среднее время на 3116 кропах.

### Пример повторной детекции

В ответе MangaLMM приведены две записи:

```json
[
  {"bbox_2d": [258, 102, 274, 116], "text_content": "とろ"},
  {"bbox_2d": [257, 101, 273, 115], "text_content": "とろ"}
]
```

При обычном расчёте площади прямоугольников их IoU составляет примерно 0,77. Одинаковый текст и почти совпадающие рамки делают их кандидатами для удаления дубликатов. Само повторение слова в разных местах страницы недостаточно для удаления: при объединении результатов нужно учитывать и расположение областей.

Размер входа модели и система координат этого конкретного примера в документе не указаны. Поэтому эти рамки не накладывались на исходную картинку и по ним не рассчитывалась точность детекции.

### Что подтверждает пример

MangaLMM возвращает структурированный результат «координаты + текст», но формат ответа сам по себе не подтверждает правильность распознавания. Manga OCR нельзя оценивать как детектор по числу возвращённых фрагментов. Большой объём текста у Tesseract также не означает высокой точности. Для выбора системы нужны эталон и метрики соответствующей задачи.

## Вывод для портфолио
